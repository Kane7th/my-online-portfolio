Case study · 2026

MySmartRental 2.0

Property management software for landlords, tenants, and property managers worldwide. One product replacing spreadsheets, WhatsApp rent chasing, and disconnected tools.

Try staging Live demo Portfolio

Problem

Small and mid-size operators run portfolios on spreadsheets, bank SMS screenshots, and chat apps. Rent status is unclear, maintenance requests get lost, and payouts need manual reconciliation per unit.

My role

Solo product engineer: product direction, data model, Next.js web app, API routes, payment integrations, landlord and tenant flows, and coordination with native iOS and Android builds.

Architecture

Public /api/health confirms API and database reachability on staging. Versioned API under /api/v1 for mobile and web clients.

What I shipped

  • Portfolio model: sites, units, leases, recurring invoices, occupancy tracking
  • M-Pesa STK push (Paybill / Till) with SMS receipts; card and bank where operators use them
  • Payment reconciliation tied to units; arrears and payout visibility
  • Maintenance tickets with photos, contractor assignment, and status workflow
  • In-app messaging and broadcast announcements for landlords and tenants
  • Multi-currency UI (KES, USD, GBP, EUR) and multi-locale support
  • Demo and sign-up funnels without forcing card details for trial units
  • Security defaults: strict transport, frame controls, sensitive payout fields handled carefully in UI

Outcomes

  • Live staging at staging.mysmartrental.com — usable today, not vaporware
  • Web + mobile — landlords and tenants on dashboard and native apps
  • Payments in product — STK push, offline recording, reconciliation in one place
  • Earlier version preserved — Flask/React MySmartRental.com (2025) shows iteration over time

Hard problems

Payments across regions

Operators expect M-Pesa where they use it, but global portfolios need card and bank options too. The UI and reconciliation layer had to treat currency and provider per operator, not as a single-country bolt-on.

One data model, two audiences

Landlords need portfolio-wide reporting; tenants need a narrow view of their lease, invoices, and tickets. Role-scoped queries and dashboards share one PostgreSQL schema without leaking cross-tenant data.

Staging as a real environment

Health checks, nginx, and production-like config on Ubuntu mean demos and QA run on infrastructure close to go-live, not only on localhost.
